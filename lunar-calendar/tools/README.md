# Data generator

`lib/data.luau` is generated by `generate_data.py` in this directory. It ships
with the plugin so the numbers can be reproduced and audited: nothing in the
plugin is hand-waved.

```sh
python3 -m venv .venv && .venv/bin/pip install lunar_python
.venv/bin/python tools/generate_data.py
```

Source of truth is [lunar_python](https://github.com/6tail/lunar-python) (the
6tail Lunar library, implementing the ShouXing 寿星天文历 algorithms). The script
does not trust it blindly: before writing anything it round-trips **every day
from 1900-01-31 to 2100-12-31** (73,384 days) back through lunar_python and
aborts on the first mismatch.

Re-running it must leave `lib/data.luau` byte-for-byte unchanged - that is the
reproducibility check, and it needs nothing but Python 3 and `lunar_python`. The
only file the script writes is `lib/data.luau` inside this plugin; pass
`--fixtures <dir>` if you also want the reference fixture the development test
suite uses.

Two tables come out of it, both plain numbers on purpose:

| Table | Row |
| --- | --- |
| `terms` | `{ year, 小寒, 大寒, 立春, ... 冬至 }` — the day of month each of the 24 solar terms falls on |
| `lunar_years` | `{ year, leap, m1 .. m12, leap_days }` — month lengths as 29/30, `leap` = leap month number (0 = none) |

At runtime `lib/lunar.luau` reads those tables directly.
